# 总览上的视觉注意力：先看哪个数字，怎样读对它

2026-11-25 · [研究问题 #47](https://github.com/JasonCodeMaker/Stack-Portfolio/issues/47) · [方案比较 #45](https://github.com/JasonCodeMaker/Stack-Portfolio/issues/45)

**建议先测试一种稳定的阅读顺序。** 打开总览，先读所选账户在指定时点值多少。往下读，能说清选定期间有多少钱来自外部转入、投资本身赚亏多少。若缺报价导致只能估出部分资产，限定语和金额同时出现。需要解释某笔变动时，再进入持仓、账户、收益复盘或汇率明细。把这个顺序与当前界面和「期间表现优先」方案放在相同数据上比较，才能判定它是否更适合本项目。

## 哪些界面做法值得拿来比较

**一个问题有一处明确的视觉重点。** Ajani 等人的对照研究比较了六个图表主题。精简装饰提高了部分主观评分；再用标题、局部高亮和注释共同指向一个数据模式，读者之后更常回忆起该模式。这项实验测量的是解释性图表的记忆。本项目可以检验同样的手段能否帮助投资者区分入金和盈亏，也要测试强调某一结论后是否漏看其他真正影响判断的因素。[作者论文，图 1、实验方法及 §5–6](https://visualthinking.psych.northwestern.edu/publications/Ajani_Declutter_2021.pdf)

**同一列回答同一个问题。** Apple Stocks 的自选列表允许整列切换价格变动、百分比或市值，证券间因此可以用同一种单位比较。可借鉴的是一致的列口径，以及从一行进入单个标的的阅读方式。组合总览还需交代入金、现金、汇率和账户范围，直接照搬股票报价列表会漏掉这些条件。持仓区可保留已选定的权重变化和累计盈亏样式，在列头或分组标题明确「权重」「相对前收」「累计盈亏」；换持仓或打开详情时保留同一期间。[Apple Stocks 使用手册](https://support.apple.com/guide/stocks/st7e0b19a267/mac) · [前五持仓的已确认选择](https://github.com/JasonCodeMaker/Stack-Portfolio/issues/36)

**比较大小用共同基线，解释趋势用一致单位。** Heer 与 Bostock 的比例估计实验中，共同刻度上的位置判断比单凭长度判断更准确。对本项目，比较哪些证券或账户贡献更大时，可用同一零点的正负条和直接金额；回答「前五大占组合多少」时，用整体份额与明确的百分数。将期间 AUD 盈亏单列或用切换展示百分比，也可检验读者能否正确识别资金流和收益率。双轴的具体效果仍要在本页测量。[作者论文，实验 1A](https://idl.cs.washington.edu/files/2010-MTurk-CHI.pdf)

**把理解数字所需的信息摆在数字旁边。** 日期、金额单位、可估值小计等决定数字含义，适合常显。分账户构成、报价来源、证券行情、计算细项可以按需查看。沿用现有资产、汇率和持仓详情入口。键盘用户已有方向键、Home、End 和报读数据点的能力，可在图旁补一条数据可支持的摘要，帮助用户无需逐日遍历也能知道主要变化。正负号与文字保留方向和状态，焦点顺序与页面阅读顺序相符；普通文字对比度以 4.5:1 为检查基准。W3C 的规范和示例给出可访问性要求与实现方式，本次没有进行整页一致性认证。[现有图表交互](https://github.com/JasonCodeMaker/Stack-Portfolio/blob/81f3216/desktop/ui/charts/LineChart.jsx#L156-L192) · [WCAG 2.2](https://www.w3.org/TR/WCAG22/) · [WAI 图表文字说明](https://www.w3.org/WAI/tutorials/images/complex/)

## 推荐原型中的第一屏

| 阅读步骤 | 普通状态 | 出现例外时 |
| --- | --- | --- |
| 1. 这是谁的账户、何时的资产？ | 保留全局账户和估值日期，将主金额与「当前估值」或历史日期成组。最新模式下，市况变动旁提供可查看的基准市场与收盘日。 | 数据只能支持部分估值时，把金额直接命名为「可估值小计」，视觉与辅助技术使用同一金额。若可定位缺项，入口写明「查看缺失报价」并带到相应持仓。 |
| 2. 这段期间发生了什么？ | 用选定期间组织投资盈亏、净流入和 TWR。金额、百分数分组。入金造成显著变动的例图可在图旁直接标明已知资金流。 | 历史截止日期早于所选日期，直接在受影响的期间数字旁写出可估值截止日。缺少成本凭据只影响持仓盈亏时，在该项显示「待补成本」。 |
| 3. 到哪里找原因？ | 盈亏构成与复盘解释期间表现；前五大持仓与账户明细定位头寸；汇率部分保留期间影响、最近折算变化与美元敞口的层级。 | 旧报价与缺报价分开处理。能够完整估值但有旧报价时，在相关证券或数据详情标注时间。主屏升格提示须有具体影响或行动，避免重复此前移除的泛化提醒。[总览已确认的决定](https://github.com/JasonCodeMaker/Stack-Portfolio/issues/36) |

16:9 下主信息按上述顺序连续阅读；21:9 可在右侧承载账户、汇率或明细，保留相同的主金额和期间分组。当前 CSS 已支持窄视窗换行、超宽屏侧栏和多账户滚动，适合用来比较不同内容顺序。超宽屏增加的空间是否缩短诊断路径，以及用户是否能发现侧栏之外的内容，需要观察任务表现。[宽高比布局与断点](https://github.com/JasonCodeMaker/Stack-Portfolio/blob/81f3216/desktop/ui/overview.css#L20-L85) · [现有主栏与侧栏](https://github.com/JasonCodeMaker/Stack-Portfolio/blob/81f3216/desktop/ui/Overview.jsx#L336-L355)

## 怎样验证优先级

使用经核算的模拟账户，给当前布局、日常检查优先、期间表现优先三种方案相同数据和导航能力。先让参与者不受提示地解释首屏，再给具体任务，轮换方案顺序和等难度数据。分别记录首次回答能否同时说明数字、日期和含义，以及首个入口、找到正确解释的时间、遗漏的限制。这样可以区分「看见数字」和「用对数字」。

| 模拟任务 | 判断答对的依据 |
| --- | --- |
| 月初 A$100,000，月末 A$111,000，本月净入金 A$10,000。问本月投资本身赚了多少，哪两个数可以核对。 | 答 A$1,000，并指出资产增加 A$11,000 中 A$10,000 是入金。仅凭这三个数不能确定精确的期间 TWR。 |
| 一个市场已经收盘，另一个市场仍沿用上次确认收盘。问主卡下的变化代表哪个时间范围。 | 指出当前模式采用各市场相应收盘基准，进入正确明细读出两个日期。切到历史模式，能辨认组合的共同可估值收盘。 |
| 一只证券缺失价格，屏上显示 A$80,000，请报出你能确定的资产金额，并找出待补项。 | 说明 A$80,000 为可估值小计，完整总额暂时未知；能找到受影响标的。配对的普通状态也要测试，记录误把完整估值当异常的次数。 |
| 在 16:9 与 21:9 窗口分别使用键盘，从主金额查看明细，返回后再读持仓正负方向。 | 焦点可见、回到原入口，能说出符号和口径。再以读屏、放大文本和灰阶检查金额、限定语及排序是否仍可辨。 |

**取舍。** 日常方案如能减少把入金当收益、把小计当总额的错误，同时让月度复盘用户仍能找到 TWR 和持仓贡献，就值得继续。若只提高偏好评分，或明显拖慢常见的复盘任务，应重新比较期间表现优先的方案。例外提示是否应升到主位置，以用户能否发现真实缺项及误报次数成对判断。

本报告于 2026-11-25 核查上述提交中的组件、计算路径、已确认 Issue、Apple 产品手册、W3C 条款及两篇研究的方法和结果相关章节。本报告的代码审查没有测量目标投资者的阅读顺序、任务时间、屏幕阅读器输出或实际误读率。
