# Domain docs

Before exploring the codebase, read the root `GLOSSARY.md` and any relevant records in `docs/adr/`. Proceed if either is absent.

Stack Portfolio uses one domain context. Keep shared terminology in `GLOSSARY.md` and architectural decision records in `docs/adr/`.

Use the glossary terms in specs, issue titles, and tests. When work exposes a missing term or a decision worth recording, use the domain-modeling skill.

When a proposal conflicts with an existing architectural decision record, identify the record and explain the reason for revisiting it.
